# v0.6.0 validation

Validated offline with Zeek 9.0.1 on 2026-11-03; no sensor deployment or live
performance test. All 125 prior synthetic cases pass; 18 new ARP cases pass
(**143 total**). Existing DJI, kresoin MAVLink and four UVic fixture regressions
also pass.

ARP synthetic coverage includes reciprocal claims, disabled-module behavior,
ARP without drone identity, one-sided claims, different owner MACs, duplicate
bursts, stale claims, requests, Ethernet/ARP sender mismatch, ignored proxies,
threshold overrides, table bounds, multicast MACs, rolling-window boundaries,
unrelated IP pairs and gratuitous self-claims. Valid transport checksums are
used in the synthetic captures.

## Reproduce

```sh
DJI_CAPTURE=/path/to/djiuav.pcap.gz python3 tests/run_tests.py
ISOT_CAPTURE_ROOT='/path/to/ISOT Drone Dataset/Raw Data' python3 tests/test_mitm_captures.py
```

Optional real fixtures report SKIP if unavailable. The MITM runner uses `-C` for
offline payload analysis independent of captured IP transport checksums. ARP
has no application checksum; the Tello binary CRC checks remain enabled.

## Limits

This is a specific ARP-pattern detector, not a general MITM verdict or proof of
command modification. Proxy ARP and temporally duplicated captures can reproduce
the evidence. Three normal captures do not establish a general false-positive
rate. One-sided attacks, IPv6, absent ARP, multiple broadcast domains sharing
addresses and worker-split traffic remain limitations. Alerts enrich the next
eligible protocol record; there is no independent immediate ARP emission or
session-end flush. See the README before enabling the module.
