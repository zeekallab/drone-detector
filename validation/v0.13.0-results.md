# v0.13.0 validation

Tested with Zeek 9.0.1 on 2026-11-04.

- `python3 tests/run_tests.py`: all 221 synthetic scenarios and available UVic/
  kresoin capture regressions passed.
- `python3 tests/test_cluster.py`: four real loopback Broker processes (manager,
  proxy and two workers) passed. SDK UDP-content events go only to the state
  worker; H.264 events go only to the video worker. Before shared confirmation,
  video does not log; afterward exactly one H264 video record is written.
  A burst of 100 SDK messages produces one initial publication, with a later
  refresh producing one more. Expiry, out-of-order/stale/future evidence and
  receiver capacity/overflow signaling are checked. The fixture uses synthetic
  application events rather than physical packet capture or sensor load testing.
- Real `video_6_5_14_5mins.pcap`, copied from the user's ubuntu5 replay host:
  six tello-video records, six SDK records and six binary records, no reporter
  errors, using standalone Zeek with `-C`. Source credit remains University of
  Victoria ISOT; the capture is not redistributed.

Live Corelight worker assignment has not been established, and this change has
not been deployed to the AP200. It addresses the confirmed implementation
limitation; the sensor replay is still needed to verify the reported symptom.
